# Security policy

## Supported version

Security fixes target the latest commit on `main`.

## Reporting a vulnerability

Do not publish sensitive details in a public issue. Use the repository's
**Security** tab and GitHub's private vulnerability reporting flow when it is
available. If that option is unavailable, contact the maintainer through the
GitHub profile and request a private channel before sharing reproduction data.

Include:

- affected route or component;
- impact and required preconditions;
- minimal reproduction steps;
- whether personal data or credentials may be involved;
- a suggested mitigation, if known.

Never include real passwords, session tokens, database URLs or third-party user
data in a report.

## Response

The maintainer will acknowledge a valid report, reproduce it privately, prepare
a focused fix and disclose details only after users can update. Portfolio
availability does not imply a guaranteed response time.
